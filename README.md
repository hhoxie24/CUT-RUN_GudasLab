# CUT&RUN Analysis Pipeline

A modular pipeline for CUT&RUN (Cleavage Under Targets & Release Using Nuclease) data analysis, with E. coli spike-in normalization. Developed for paired-end Illumina sequencing data aligned to mm10 (mouse), adaptable to other reference genomes.

## Experiment

- **Assay**: CUT&RUN with E. coli K-12 MG1655 spike-in DNA
- **Targets**: H3K27me3 (3 reps), H3K4me3 (2 reps), RARg (3 reps), RXRa (3 reps), IgG control (3 reps) — 14 samples total
- **Genome**: GRCm38/mm10 (4DN Consortium bowtie2 index, no alt contigs)
- **Sequencing**: Paired-end, Illumina TruSeq adapters

## Pipeline Overview

```
00_setup_conda_envs.sh    Create CNR + DEEPTOOLS conda environments
00b_preflight_check.sh    Validate tools, indices, FASTQs, disk space
02_align_spikein_v2.sh    Trim → Align → MarkDup → QC → MAPQ30 filter → Spike-in
03_bw_bg_v2.sh            Spike-in BigWigs + SEACR bedGraphs + CPM BigWigs
03b_bw_dedup_v2.sh        Same as 03 but from deduplicated BAMs (optional)
04_peakcall_v2.sh         SEACR peak calling (MACS3 section commented, available)
05_merge_annotate_v2.sh   HOMER mergePeaks + annotatePeaks (merged replicates)
06_indiv_annotate_v2.sh   HOMER annotation of individual replicate peaks
07_bedtoolsint_v2.sh      Bedtools intersect for replicate overlap (RARg)
```

## Setup

### 1. Install prerequisites

**Conda environments** (miniforge required on Apple Silicon):

```bash
brew install --cask miniforge    # macOS
conda init zsh                   # or bash
# If Anaconda is in PATH, reverse it first:
# /opt/anaconda3/bin/conda init --reverse zsh
```

Then run `00_setup_conda_envs.sh` to create both environments.

**HOMER** (installed outside conda):

```bash
mkdir -p ~/Homer && cd ~/Homer
wget http://homer.ucsd.edu/homer/configureHomer.pl
perl configureHomer.pl -install homer
perl configureHomer.pl -install mm10
```

**SEACR**:

```bash
curl -L https://raw.githubusercontent.com/FredHutch/SEACR/master/SEACR_1.3.sh \
  -o /path/to/SEACR_1.3.sh
```

### 2. Configure paths

Edit `config.json` with your system-specific paths:

```json
{
    "project_dir": "/your/project/directory",
    "genome": {
        "bowtie2_index_mm10": "/path/to/mm10/index_prefix",
        "bowtie2_index_ecoli": "/path/to/ecoli_K12/index_prefix"
    },
    "tools": {
        "homer_bin": "/path/to/Homer/bin",
        "seacr_script": "/path/to/SEACR_1.3.sh"
    }
}
```

Each script sources paths from `config.json` via the helper function in `scripts/parse_config.sh`.

### 3. Validate setup

```bash
zsh 00b_preflight_check.sh 2>&1 | tee preflight.log
```

### 4. Organize FASTQs

Place paired FASTQ files in `<project_dir>/02_fastq/`:

```
02_fastq/
  WT_H3K27me3_1_S3_L001_R1_001.fastq.gz
  WT_H3K27me3_1_S3_L001_R2_001.fastq.gz
  ...
```

Naming convention: `WT_<TARGET>_<REP>_<SAMPLEID>_L001_R{1,2}_001.fastq.gz`

## Running the Pipeline

```bash
# Each script is self-contained: activates its own conda env, detects CPU cores
zsh 02_align_spikein_v2.sh 2>&1 | tee 02_align_$(date +%Y%m%d_%H%M%S).log
zsh 03_bw_bg_v2.sh         2>&1 | tee 03_bw_bg_$(date +%Y%m%d_%H%M%S).log
zsh 04_peakcall_v2.sh       2>&1 | tee 04_peakcall_$(date +%Y%m%d_%H%M%S).log
zsh 05_merge_annotate_v2.sh 2>&1 | tee 05_merge_$(date +%Y%m%d_%H%M%S).log
zsh 06_indiv_annotate_v2.sh 2>&1 | tee 06_indiv_$(date +%Y%m%d_%H%M%S).log
zsh 07_bedtoolsint_v2.sh    2>&1 | tee 07_intersect_$(date +%Y%m%d_%H%M%S).log
```

## Key Design Decisions

### Adapter trimming (script 02)

Trim Galore is run before alignment. The raw FASTQs had been pre-filtered by fastp (QC-only mode with minimal adapter removal at ~0.76%). Trim Galore catches short adapter tails that fastp's default settings missed, which improves end-to-end alignment rates.

### Alignment mode (script 02)

Changed from `--local --very-sensitive-local` to `--end-to-end --very-sensitive --dovetail`. Rationale: after adapter trimming, reads should not contain adapter sequence, making local alignment (soft-clipping) unnecessary. `--dovetail` is required for CUT&RUN because MNase-digested fragments shorter than the read length produce mate pairs that extend past each other's 5' ends. `-X 700` (max insert size) replaces the original `-X 1000`, consistent with the CUT&RUN fragment size distribution for mm10 chromatin.

### Duplicate handling (script 02)

Duplicates are flagged (marked) but retained in the primary BAMs. CUT&RUN uses MNase, which cuts at stereotypic positions at chromatin boundaries, producing legitimate identical fragments that are not PCR artifacts. Both BAM types are generated per sample: `mapq30.bam` (dups retained, used for peak calling) and `mapq30.dedup.bam` (dups removed, available for comparison). In this dataset, IgG duplication rates (7.9–10.6%) were not elevated relative to targets (8.9–11.3%), so non-deduplicated BAMs were used for the primary analysis track. The lower IgG duplication rate reflects shallower sequencing depth for controls rather than higher library complexity.

### SEACR bedGraph generation (script 03)

Switched from bamCoverage binned output to the SEACR-recommended bedtools fragment-based method: `bamtobed -bedpe → genomecov -bg`. This preserves exact fragment coordinates rather than binning signal into fixed windows, which is required for SEACR's internal statistical model. Spike-in scale factors are applied post-hoc via awk multiplication.

### SEACR normalization mode (script 04)

Changed from `norm` to `non` in the SEACR call. The input bedGraphs are already multiplied by spike-in scale factors (from `spikein_normalization.tsv`). Using SEACR's internal `norm` mode on pre-normalized data would apply double normalization, distorting the target-vs-control comparison.

### BigWig parameters (script 03)

Removed `--centerReads` from bamCoverage. This flag shifts each read to its fragment midpoint, which is appropriate for narrow TF binding but not for broad histone marks like H3K27me3 where the full fragment extent carries biological information. `--extendReads` (extending each read to the inferred fragment length) is retained.

### Spike-in normalization (script 02, Step 2)

Scale factors are computed as `min(spike_fraction) / sample_spike_fraction`, where `spike_fraction = ecoli_unique / mm10_unique`. The sample with the lowest E. coli fraction (least spike-in relative to target genome) receives a scale factor of 1.0; all others are scaled down proportionally. This corrects for differences in both technical spike-in variation and biological input (cell count) variation across samples.

## Conda Environment Architecture

Two separate conda environments are used to avoid dependency conflicts on arm64:

- **CNR**: bowtie2, samtools, bedtools, picard, trim-galore, cutadapt, macs3, multiqc, openjdk 17
- **DEEPTOOLS**: deeptools, samtools, bedtools

Picard (Java) calls Rscript internally for histogram PDFs; the conda R installation on arm64 has broken `@rpath` resolution for `libgfortran.5.dylib`. Deeptools bundles pysam/htslib, which conflicts with Picard's JDK requirements. Splitting the environments keeps each solver space small and resolvable.

## Known Warnings (Inconsequential)

**`libgkl_compression.dylib` / `IntelInflater` warnings**: Appear in every Picard run on Apple Silicon. Picard bundles an x86_64 Intel compression library that cannot load on arm64. Picard falls back to the Java deflater with no impact on output correctness or performance.

## Platform Notes

Developed and tested on Apple M2 Ultra Mac Studio (16 P-cores, 8 E-cores, 128GB RAM, macOS 15.1). All scripts auto-detect Apple Silicon P-core count via `sysctl hw.perflevel0.logicalcpu` and use only performance cores to avoid efficiency-core sync bottlenecks. On non-Apple systems, scripts fall back to `hw.ncpu` (Linux: `nproc`).
